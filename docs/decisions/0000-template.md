# ADR NNNN - Short decision title

Status: proposed / accepted / superseded
Sprint: SXXX
Requirements: SRS section and requirement IDs
Date: YYYY-MM-DD

## Context

State the concrete ambiguity or implementation constraint and the evidence.
Distinguish source requirements from assumptions. Link the affected contract.

## Decision

State the behavior, ownership, boundaries, and failure handling precisely enough
that another implementation task will make the same choice.

## Consequences and verification

List relevant migration/API/privacy/operational effects and the checks that prove
the decision works. If an external input is missing, name it and the blocked
sprints. Do not turn an unavailable fact into an invented default.

## Alternatives considered

Briefly record a meaningful alternative and the reason for the chosen approach.
Link a replacement ADR when superseding this one.
