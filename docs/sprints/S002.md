# S002 - Backend foundation

Completed: 2026-10-05. Prerequisite: [S001](S001.md).

## Delivered

- Django/DRF project under `backend/config/`, with explicit development, test and
  production settings, management command entry point, and WSGI/ASGI entry points.
- PostgreSQL URL configuration through Psycopg 3. Non-PostgreSQL URLs are rejected;
  tests use `TEST_DATABASE_URL` and ignore the developer's `DATABASE_URL`.
- Public, read-only `GET /api/health` (plus HEAD), returning only `{"status":"ok"}`
  with `Cache-Control: no-store`. It does not query the database. New DRF views
  default to denied access.
- Production startup checks for missing secrets/hosts/database configuration,
  example credentials, invalid database URLs and debug mode. HTTPS redirects,
  secure cookies and host checks are enabled; trusted proxies remain a deployment
  configuration responsibility.
- `pyproject.toml`, `.python-version`, hashed `uv.lock`, Ruff and pytest-django
  configuration, settings/health regression tests, updated `.env.example` and
  exact install/check/migrate/run instructions in the root README.
- Architecture, API, database, security and contributor guides distinguish the
  implemented foundation from later features.

Auth/admin/session applications are not installed in this skeleton. This avoids
creating Django's default User tables before S005 introduces the custom User.
S008 adds session authentication after the accounts model exists. No business API,
account migration, frontend, worker, Compose service or CI workflow was added.

## Dependency decision

Verified on local Linux x86-64, Python **3.14.7**, uv **0.12.23**. Locked runtime
dependencies include Django **5.2.17**, DRF **3.18.1**, Psycopg/binary **3.3.6** and
dj-database-url **3.1.2**. Development tools include pytest **9.1.1**,
pytest-django **4.14.0** and Ruff **0.16.10**. `uv.lock` is the complete version/hash
authority, including transitive and platform-specific packages.

Django 5.2 was selected for its LTS support through April 2028, confirmed against
the [official supported-version table](https://www.djangoproject.com/download/).
Compatibility was checked against the [Django release notes](https://docs.djangoproject.com/en/5.2/releases/5.2/)
and [DRF release notes](https://www.django-rest-framework.org/community/release-notes/),
then verified by installation and tests. Routine commands use `--locked`, following
the [uv locking documentation](https://docs.astral.sh/uv/concepts/projects/sync/),
so stale project metadata fails rather than silently changing resolved versions.
Future security/dependency updates must review the lockfile and rerun the gates.

### PostgreSQL and HTTP smoke check

Started an isolated, disposable `postgres:17` container with synthetic credentials,
an ephemeral loopback port and no existing database or host data mounted. The
resolved image was PostgreSQL **17.11**, image digest
`sha256:d74eeac9a635390a49bc21bd49fccd973de707e2a53a76ac49b552b8712ec46f`.

- With `DATABASE_URL` pointing only at that database,
  `.venv/bin/python backend/manage.py migrate --noinput` succeeded: no migrations
  to apply. A direct Django/Psycopg query confirmed PostgreSQL and the intended
  database, and introspection confirmed that `auth_user` did not exist.
- Started `backend/manage.py runserver 127.0.0.1:<ephemeral-port> --noreload`,
  fetched `/api/health` over HTTP, and verified 200, the exact JSON and no-store.
- `backend/manage.py check --settings=config.settings.production` passed with
  generated/synthetic configuration (no real credentials or production access).
- Stopped the development server and ran `docker stop aarchive-s002-postgres`;
  `--rm` removed the disposable container and its temporary storage.

These checks verify the foundation, not future account/grade/import behavior.
There is no database schema migration or compatibility change to existing user
data. G01 exporter schemas remain an external input for S025; they do not affect
this sprint. S003 supplies the frontend foundation; S004 supplies shared local
services and CI. Production deployment is still later work.
