# S003 - Frontend foundation

Completed: 2026-10-06. Prerequisite: [S001](S001.md). Requirements: SRS Sections
27, 28, 47 and Appendix A; accepted decision D01.

## Delivered

- React/TypeScript/Vite project, BrowserRouter, strict type checking, ESLint,
  Vitest/Testing Library, Playwright/axe, and exact npm dependency lockfile.
- Responsive shell with a navigation slot, skip link, semantic landmarks and
  route-change focus. Shared page heading, button, labeled input with associated
  hints/errors, focused error summary, loading and empty-state components.
- A development-only `/dev/primitives` workshop with synthetic form validation,
  reset, loading and empty-state interactions. All state remains in memory;
  no backend calls, fake login, feature dashboards or production records.
- Same-origin session/CSRF API client with typed errors, safe fallback messages,
  cancellation and validated pagination envelopes/links. The detailed interface
  is documented in [api.md](../api.md#frontend-client-s003).
- Root README setup/check commands and updated architecture/contribution/security
  guides. No database migration or change to the backend health contract.

The production build has only the foundation overview and fallback route. The
workshop route and module are excluded. S004 adds local backend/service routing
and CI; S008 supplies the actual session and CSRF bootstrap. The client alone does
not implement authentication or authorization.

## Dependencies and verification environment

Local Linux x86-64, Node **22.23.1**, npm **10.9.8**. Exact dependencies are in
`frontend/package-lock.json`, including React **19.3.0**, React Router **7.18.4**,
TypeScript **6.0.3**, Vite **8.3.2**, Vitest **5.0.3**, Playwright **1.63.0** and
axe **4.13.0**. Node types match the Node 22 runtime. Package versions are exact,
and `npm ci` checks the lockfile against the manifest.

The [Vite Node requirements](https://vite.dev/guide/),
[React Router declarative installation](https://reactrouter.com/start/declarative/installation),
and Django's [CSRF client guidance](https://docs.djangoproject.com/en/5.2/howto/csrf/)
inform the setup. No additional authentication scheme or cross-origin token
transport was introduced.

## Browser and visual review

The browser run tested Chromium at **1440×1000** and **390×844**, with additional
overflow assertions at **320px** width. It verified skip navigation, visible
keyboard focus, error-summary-to-field focus, associated error descriptions,
successful validation/reset, loading announcements, reduced-motion behavior,
route focus, history navigation and empty browser storage.

Automated axe scans found no violations in the tested error and empty states at
desktop/mobile widths. This is scoped evidence, not a claim of universal
accessibility certification. Desktop/mobile full-page screenshots were visually
reviewed for text, spacing, overflow and controls. Screenshots live in ignored
`frontend/test-results/` and can be regenerated by the browser tests. An audit's
temporary focus was reset to a real control before the review captures.

The production-preview test confirmed `/dev/primitives` resolves to the fallback
page and exposes no workshop controls or navigation. Test servers shut down at
completion. Playwright used its Ubuntu fallback Chromium build on this host;
all browser checks passed without changing system libraries.
