# S008 — Session login and logout

Completed 2026-10-09 after resuming interrupted work from 2026-10-07.
Prerequisites S004-S007 were verified against their implementation and evidence.
Scope: AUTH-001; SRS 16.1, 18, 46; D01/D02. No registration, password recovery,
OAuth, production deployment, remote push or real-account provisioning was added.

## Delivered

- Database session authentication for the custom platform user; Django
  auth/contenttypes/session migrations without a default `auth_user` table.
- CSRF-protected login/logout, current-session bootstrap and bounded, generic
  JSON errors. Secure production cookies and absolute session expiry.
- PostgreSQL email/peer attempt windows with row locking, finite recovery,
  keyed identifiers and cleanup command. Blocked peers cannot allocate new
  identifier rows; forwarded headers cannot bypass the peer budget.
- Current-state session revocation, password-hash invalidation and audited
  INACTIVE reactivation. Login/logout persistence and audit are transactional.
- Sign-in/account pages using the existing same-origin client, runtime response
  validation, password clearing, error focus, retry and confirmed sign-out.
- Safe audit schemas for failure, threshold, success and session end. Real
  sessions reach the existing current-state Administrator audit policy.
- Isolated real-browser runner and CI integration, with guarded synthetic
  suspension fixtures and independent screenshot output directories.

The [authentication guide](../authentication.md) is the API/configuration/operations
contract. API, database, security, access, audit, architecture, README and decision
summaries were updated to match the implemented state.
