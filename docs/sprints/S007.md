# S007 - Central role and scope policy interface

Completed: 2026-10-07. Prerequisites: [S005](S005.md), [S006](S006.md).
Requirements: SRS Sections 9, 10, 18 and 48; D02/D04.

## Delivered

- `backend/apps/access/`: fresh account/role authorization, typed `ResourceRef`,
  registered queryset selectors, shared list/detail checks and DRF permission helper.
  Unknown actions/kinds, source identities and wrong models deny by default.
- Audit API integration with the central gate and scoped queryset; its global
  Administrator-only contract is unchanged. No new write endpoint or screen.
- Explicit `set_roles` and `set_grant` services, requiring current Administrator
  authority and controlled nonempty reasons. Changes and audit commit or roll
  back together. No mass assignment of credentials/source fields is accepted.
- ScopedGrant with unique typed capability/scope/subject tuple and database checks.
  A seeded PrivilegeLock serializes edits, protecting against concurrent privilege
  races. Last eligible Administrator removal is denied; Teacher removal revokes
  active delegated grants with audit. Repeats are no-ops; revocations retain rows.
- Local `bootstrap_administrator --email` command for an existing verified/approved
  eligible account, only while no Administrator assignment exists. It records a
  system-actor audit and creates no account or password.
- Reviewed UUID/capability/scope grant audit schema and bootstrap system actor.
- [Developer integration guide](../access.md), migration/locking instructions,
  updated audit coverage, security/API/database/architecture guides and README.

Only the audit resource policy is deployed. Fixture policies exercise owner,
other-student, assigned/unassigned teacher and admin scopes without pretending
that academic models exist. Grant activation requires registered existing scope
objects, so real offering/contest/group delegations wait for those domain modules.
Complete visibility resolution is still S019. Session transport/login is S008.
Optional delegated own-action audit reads remain separate future scoped work;
the existing global audit route is not widened.

## Handoff

Apply migrations with the README command. Full reversal drops grant data, so use
forward repair and tested backups once grants exist. Future lifecycle mutations
must acquire `lock_privilege_changes()` before User/resource locks and enforce
last-admin/account invariants. Future domain adapters must provide real DB scope
and privacy predicates; raw ORM/direct database writes are trusted internal tools,
not authorized request or importer interfaces.

S008 should connect session identities to the central permission helpers and test
real browser login/logout, CSRF and forbidden-state rejection. G01 still affects
S025's trusted exporter contract; it does not block the authentication sprint.
