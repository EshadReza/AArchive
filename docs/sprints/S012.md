# S012 — Departments, batches, terms and sections

Completed 2026-10-09 for ADMIN-010, SRS 13/16.2/43/44 and D03. Prerequisite
S003 frontend primitives, S005 account models, S006 audit and S007 authorization
were checked in the code before implementation.

## Delivered

- UUID Department, Batch, Term and Section models with protected typed parents,
  canonical labels, scoped uniqueness, archive flags and positive revisions.
- Atomic audited batch creation with its reserved `ALL` section. Labels stay unique
  across archived records. PostgreSQL triggers prevent parent reassignment and
  changing/archiving reserved ALL sections independently.
- Administrator-only paginated create/read/edit/archive APIs with strict payloads,
  revision conflicts, CSRF and authorization before lookup/counting. No hard delete.
- `/admin/structure` management screen using shared form/button/loading primitives
  and a semantic table, paginated named parent selection, filters, create/edit forms,
  and focused archive review/cancel/confirm. `/account` links to it for Administrators.
- Archive retains all history, marks descendants unavailable and blocks new children
  and assignments through archived ancestors. An atomic same-parent context helper
  is the required integration boundary for future offering/assignment writers.
- Reviewed before/after academic metadata audit records, with business rollback on
  audit failure. No course/offerings/enrollment or real academic data were introduced.

The [academic structure guide](../academic-structure.md) defines exact API requests,
projections, errors, parent/ALL policy, migration effects and local browser steps.
README, architecture, API/database/security, audit/access and D03 implementation
notes were updated. Existing uncommitted project work was preserved.
