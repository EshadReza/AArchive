# S006 - Append-only audit service

Completed: 2026-10-07. Prerequisite: [S005](S005.md).
Requirements: SRS Sections 18, 20, 42 and 45; D02.

## Delivered

- `backend/apps/audit/`: indexed AuditLog with actor/target/action, previous/new
  values, reason, timestamp and explicit request context. Actor references are
  protected platform UUIDs; system actors need no fabricated User. ANONYMIZED
  users retain their references. Target identifiers survive target deletion.
- Transaction-required `record_event` service and reviewed event schemas. Unknown
  fields (including their names) are omitted before JSON validation; known fields
  are type/vocabulary checked and required when a payload is supplied. Projections
  have an 8 KiB ceiling. Reasons are controlled codes. No automatic raw request,
  session, browser-agent or header capture occurs; optional IP recording is explicit.
- Model/queryset mutation guards and a PostgreSQL trigger rejecting UPDATE/DELETE.
  Bulk insertion is disabled in favor of individual service calls. Database owner
  DDL/TRUNCATE is outside this application's immutability boundary.
- Read-only `GET /api/audit` and `/api/audit/{id}`, with HEAD, current-state/role
  Administrator permission checks, no-store responses, safe projections and
  bounded cursor pagination. Invalid cursor positions are rejected before queries.
  Expected errors follow the planned code/message/request_id envelope.
- `audit.0001_initial` and `0002_append_only`, plus 51 new behavior checks.
- [Audit integration guide](../audit.md), action naming and feature coverage
  checklist, API/database/security/architecture guidance and current README status.

The event catalogue is an integration contract, not an implementation of account
mutations or system maintenance jobs. S007 integrates shared authorization and
audited role edits. S008 must wire and test actual sessions; production HTTP
requests currently fail closed because no authenticator is installed. Authorized
read tests use DRF's test authentication helper. No log dashboard or backfill was
added. Event delivery/outbox is S023. New feature schemas must be reviewed and
tested rather than accepting arbitrary objects into the immutable log.

## Migration and handoff

Run the README migration command before using the service. Once real audit
evidence exists, use forward corrective migrations and tested backups; rolling
back these migrations would drop evidence and must not be a routine deployment
rollback. Production runtime-role/DDL restrictions remain operational work.

Future features must register safe schemas and invoke `record_event` inside their
authorized business transaction. Let audit failures abort the mutation. For
standalone failed-login/security events, explicitly open a separate transaction;
never reuse the failed business transaction. S007 should retain the current global
Administrator-only audit scope, and S008 should verify real session transport.
G01 (trusted exporter schema contents) still affects S025, not this sprint.
